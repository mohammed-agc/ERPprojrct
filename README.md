# ERP System — Vehicle Trading & Workshop

Arabic-first (RTL) enterprise resource planning system for vehicle trading,
spare parts, workshop, and financial operations. Built on React + Vite +
Tailwind + shadcn/ui with Lovable Cloud (Supabase) as the backend.

**Current release:** [ERP Core Freeze v1.0](docs/ERP_CORE_FREEZE_V1.md)
**Architecture:** [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
**Changelog:** [CHANGELOG.md](CHANGELOG.md)

---

## 1. Project Overview

A double-entry accounting ERP with department- and role-scoped access
control. Every operational transaction (purchase, sale, return, payment) is
posted to the General Ledger, and every per-VIN sale is reconciled against
landed cost for true profitability.

**Stack**
- Frontend: React 18, Vite 5, TypeScript 5, Tailwind v3, shadcn/ui, React Query
- Backend: Lovable Cloud (Postgres + Auth + Storage + Edge Functions)
- Lang: Arabic UI (RTL), Hijri/Gregorian dates
- Package manager: bun (npm/pnpm also work)

## 2. Installation

```bash
git clone <your-repo-url>
cd <repo>
bun install         # or: npm install
```

Requires **Node.js ≥ 20** and **bun ≥ 1.0** (or npm 10+).

## 3. Environment Setup

`.env` is auto-generated by Lovable Cloud and **must not be edited manually**.
After connecting Cloud (or a self-hosted Supabase project), it contains:

```
VITE_SUPABASE_URL=...
VITE_SUPABASE_PUBLISHABLE_KEY=...
VITE_SUPABASE_PROJECT_ID=...
```

For self-hosted setups, create `.env.local` mirroring those three keys.

---

## 4. Supabase / Lovable Cloud Setup

### Option A — Lovable Cloud (recommended)
1. Open the project in Lovable.
2. Cloud is enabled by default; the schema and migrations apply automatically.
3. Use the **Cloud** panel for tables, auth, storage, and logs.

### Option B — Self-hosted Supabase
1. Create a new Supabase project.
2. Copy the project URL, anon key, and project ref into `.env.local`.
3. Apply migrations (see §6).
4. Deploy edge functions: `supabase functions deploy incentive-api incentive-authz`.

## 5. Running Locally

```bash
bun run dev         # Vite dev server (http://localhost:8080 by default)
bun run build       # Production build
bun run preview     # Preview the production bundle
bunx vitest run     # Run the test suite
```

Sign in via `/auth`. The first user must be promoted to `admin` by inserting
into `user_roles` from the Cloud SQL editor:

```sql
INSERT INTO public.user_roles (user_id, role)
VALUES ('<your-auth-uid>', 'admin');
```

## 6. Migration Process

All schema changes live in `supabase/migrations/` and apply in **filename
order**. The freeze baseline ships with 19 migrations covering tables,
enums, functions, triggers, RLS policies, and governance views.

- **Lovable Cloud:** migrations apply automatically when committed.
- **Supabase CLI:** `supabase db push` (or `supabase migration up` for local).
- **Fresh recreation:** drop the `public` schema, then re-apply every file
  in order — the result matches ERP Core Freeze v1.0.

**Never edit applied migration files.** Add a new migration with a later
timestamp prefix instead.

## 8. Production Deployment Notes

- **Publish via Lovable:** Project → Publish → choose subdomain or connect a custom domain.
- **Self-hosting the static bundle:** `bun run build` outputs `dist/`; serve with any static host (Vercel, Netlify, Nginx, Cloudflare Pages). Ensure SPA-style fallback to `index.html`.
- **Edge functions** are deployed automatically by Lovable Cloud; on self-hosted Supabase use `supabase functions deploy <name>`.
- **Secrets:** never commit secret keys. Use Lovable Cloud's secret manager or the host's environment-variable settings. The `VITE_SUPABASE_PUBLISHABLE_KEY` (anon key) is safe to ship.
- **Database backups:** enable daily automatic backups in Supabase / Cloud settings before going live.
- **First-time hardening checklist:**
  - Promote at least one user to `admin` via `user_roles`.
  - Configure departments and assign each user a `department_id` on their profile.
  - Review the security findings panel and resolve any errors.
  - Set financial period start date and lock prior periods.
  - Configure number sequences (invoices, journals, credit notes) in Admin → Settings → Sequences.
