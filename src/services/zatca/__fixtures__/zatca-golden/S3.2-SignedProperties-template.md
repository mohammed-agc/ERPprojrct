# S3.2 SignedProperties — Verified Hash Template

Every fact below was reproduced byte-for-byte against a real ZATCA-aligned accepted invoice
(Standard_Invoice_Signed.xml, genuine ZATCA test certificate).

## The hash-version template (EXACT)

The string that gets SHA-256'd is below. Indentation and line endings are load-bearing —
one wrong byte changes the hash and the invoice is rejected.

- Line endings: LF (\n) only. Never CRLF.
- `xmlns:xades` is declared on the SignedProperties element itself (hash version).
- `xmlns:ds` is repeated on EVERY ds: element.
- Indentation per line (leading spaces):

```
0   <xades:SignedProperties xmlns:xades="http://uri.etsi.org/01903/v1.3.2#" Id="xadesSignedProperties">
32  <xades:SignedSignatureProperties>
36  <xades:SigningTime>{SIGNING_TIME}</xades:SigningTime>
36  <xades:SigningCertificate>
40  <xades:Cert>
44  <xades:CertDigest>
48  <ds:DigestMethod xmlns:ds="http://www.w3.org/2000/09/xmldsig#" Algorithm="http://www.w3.org/2001/04/xmlenc#sha256"/>
48  <ds:DigestValue xmlns:ds="http://www.w3.org/2000/09/xmldsig#">{CERT_DIGEST}</ds:DigestValue>
44  </xades:CertDigest>
44  <xades:IssuerSerial>
48  <ds:X509IssuerName xmlns:ds="http://www.w3.org/2000/09/xmldsig#">{ISSUER}</ds:X509IssuerName>
48  <ds:X509SerialNumber xmlns:ds="http://www.w3.org/2000/09/xmldsig#">{SERIAL}</ds:X509SerialNumber>
44  </xades:IssuerSerial>
40  </xades:Cert>
36  </xades:SigningCertificate>
32  </xades:SignedSignatureProperties>
28  </xades:SignedProperties>
```

## Placeholders

| Placeholder | Source | Format |
|---|---|---|
| {SIGNING_TIME} | EGS clock at signing | e.g. 2025-02-27T20:52:40 (no timezone suffix) |
| {CERT_DIGEST} | SHA-256(base64 cert STRING) then base64 | 88 chars (base64-of-hex) |
| {ISSUER} | cert issuer DN | CN=..., DC=extgazt, DC=gov, DC=local |
| {SERIAL} | cert serial number | decimal integer string |

## Then

1. SHA-256 the filled template -> 64-char hex
2. base64 the hex string -> 88-char DigestValue
3. Place into Reference[@URI='#xadesSignedProperties']/ds:DigestValue

## Submission vs hash version

The version EMBEDDED in the final invoice differs from the hash version:
- embedded: xmlns:xades lives on the parent QualifyingProperties, NOT on SignedProperties
- embedded: ds: elements do NOT carry redundant xmlns:ds
- The hash is computed ONLY on the hash version above; the embedded version is what ships.
